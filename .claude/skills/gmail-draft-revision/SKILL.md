# Gmail下書きの修正ルール（中野さんの修正版を正とする）

中野さんは、私が作ったGmailの下書きをGmail上で直接添削することがある。
**中野さんが修正した下書きが常に「正」（最新版）であり、以後の追加・上書き・指示は、すべてその正の文面を土台にして行う。**
私が以前に作った文面や、会話に残っている自分の下書きの文章を土台にしてはいけない。

## 手順

1. **最新の下書きを読む（必ず最初に）**
   - `list_drafts`（`view: DRAFT_VIEW_FULL`、宛先や件名で絞り込み）または `get_draft` で、対象の下書きの現在の本文・宛先・CC・件名・添付を取得する。
   - 同じスレッドに下書きが複数あるときは、日時が新しいものと中野さんの手が入っているものを特定し、どれを土台にするか迷う場合は中野さんに確認する。
   - 会話の中にある自分の過去の下書きの文面とは比べるだけにし、違いがあれば、それは中野さんの添削として尊重する。

2. **正の文面に、依頼された変更だけを加える**
   - 中野さんの言い回し・削除・追加・順番は、指示がない限り一切変えない。
   - 追加する節や文は、正の文面の流れ（見出しの番号、敬語、改行の仕方）に合わせる。
   - 番号をずらす必要があるときは、ずらした箇所を報告する。
   - 依頼外の箇所を直したほうがよいと思ったら、直さずに提案として伝える。

3. **下書きを更新する**
   - 添付がない下書きは `update_draft` で正の文面＋変更を反映してよい。
   - 添付を付ける、または `update_draft` で引用・署名・添付が消えるおそれがある場合は、**新しい下書きを別に作り、元の下書きは消さずに残す。**

4. **下書きは消さない**
   - `delete_draft` は、中野さんが明示的に「消して」と言った場合だけ使う。
   - 新しい版を作ったときは「旧版の下書きが残っています。不要なら削除してください（指示があれば私が削除します）」と伝える。

5. **報告**
   - どの下書き（日時・リンク）を土台にしたか、何を追加・変更したかを短く伝える。
   - 中野さんの修正部分には手を入れていないことを明記する。

## 背景

2026年11月23日、榊原様あてのリマインドの下書きを中野さんが添削中に、私が添付付きの新しい下書きを作って元の下書きを削除し、添削内容を失った。
Gmail APIで削除した下書きは復元できない。このルールはその再発防止のためのもの。
