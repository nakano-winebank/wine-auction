# WineBank デッキ トンマナ

WineBankの資料は、**ダークなワインセラーの中に金の文字が浮かぶ**印象で統一する。
読み手は経営者・プライベートバンカー・証券会社であり、彼らが見慣れているのは
NOT A HOTELや金融機関のIRだ。安っぽさと情報過多がいちばんの敵になる。

## 使い方

`scripts/deck_lib.js` にパレットとヘルパーが入っている。これを読み込めば、
配色・余白・フォント・影の設定を毎回書き直さずに中身だけ書ける。

```js
const D = require("<skill>/scripts/deck_lib.js");
const { pres, C, G, t, base, card, badge, banner, tb, hdr, cel, lft, tableEnd, save } = D.init("デッキ名");

const s = base("KICKER", "スライドタイトル", "サブタイトル一行");
card(s, G.M, G.BODY_TOP, G.C3, 2.5);
badge(s, G.M + 0.3, G.BODY_TOP + 0.24, 1);
s.addText("見出し", t({ x: G.M + 0.78, y: G.BODY_TOP + 0.26, w: 2.8, h: 0.32,
  fontSize: 14, bold: true, color: C.GOLD_L }));

save("/abs/path/out.pptx");
```

既存デッキに追記するだけなら、そのデッキの生成スクリプト（`build_deck.js` 等）が
残っているはずなので、ライブラリを取り込み直すより**同じスクリプトにスライドの
ブロックを足すほうが速く、トンマナも確実に揃う**。

## 色の使い分け

| 用途 | 色 |
|---|---|
| 背景（全画面の6〜7割） | `BG` 1A0E14 |
| カード | `PANEL` 2A1620 ／ 強調は `PANEL2` 38202C（1枚に1つまで） |
| 表ヘッダ・締めのバナー | `BURG` 7B1E3A |
| 数字・バッジ・キッカー | `GOLD` C9A227 |
| カード見出し・バナー本文 | `GOLD_L` E8CE78 |
| 本文 | `TEXT` F2EDE6 ／ 補足は `MUTE` A2908C |
| プラスの数字 | `MINT` 7FD1AE |
| 注意・要検討 | `AMBER` E0A458 |
| マイナスの数字・不可 | `RED` D96A6A |

**やらないこと**：タイトル下のアンダーライン、装飾の色帯、カード端の細い
アクセントストライプ。AI生成に見える最短ルートなので使わない。区切りたい
ときは余白か、背景の濃淡か、金の丸バッジで表現する。

## レイアウトの型

`base()` がキッカー(y=0.34)・タイトル(y=0.62, 29pt)・サブタイトル(y=1.26)・
フッター(y=7.04)を置く。本文は **y=1.78 から 6.62 まで**が使える範囲。

| 列数 | 幅 | x |
|---|---|---|
| 2列 | `G.C2` 5.90 | `G.M + i*6.16` |
| 3列 | `G.C3` 3.86 | `G.M + i*4.14` |
| 4列 | `G.C4` 2.85 | `G.M + i*3.07` |

同じ型を続けない。表・カード・大きな数字・比較の2枚組・横並びのフローを
混ぜる。タイトルだけ中央寄せ、本文は必ず左寄せ。

## はみ出しと重なりを防ぐ

**この2つが実制作でほぼすべての手戻りの原因になる。** 先に計算する。

**表の下端** = `tableEnd(y, rowH)` = y + rowH の総和。
表の下にカードを置くときは、必ず `tableEnd() + 0.12` 以降から始める。
行数を1行足したのに下のカードを動かし忘れると、**最終行がカードで隠れる**。
レンダリングするまで気づかないので、コード上で計算しておく。

**日本語テキストの高さ** = `textHeight(text, boxWidth, fontSize, lineSpacing)`。
全角は1文字あたりおよそ `fontSize/72` インチ。1行の文字数は `箱幅 ÷ (fontSize/72)`。
カード内の本文は、カード下端から 0.1 以上の余裕を残す。足りなければ
フォントを下げるのではなく**文章を削る**ほうが結果が良い。

**配列のインデックス**：色やカードの塗りを配列で回すときに1つずれると、
暗い背景に暗い文字が出て事実上読めなくなる。レンダリング前に、色を保持する
要素の位置を数え直す。

## 文章の書き方

- スライドのタイトルは**全角20文字以内**（29ptで12.06インチに収まる限界が約30文字）
- 断定形で書く。「〜と思われます」ではなく「〜です」
- カード本文は3〜4行。同じスライド内のカードは行数を揃える
- 締めのバナーは1文。数字か、意思決定を1つだけ含める
- 数字は必ず単位を書く（万円／年率／連結・単体の別）

## 仕上げの確認（省略しない）

```bash
node build_deck.js
python <pptx-skill>/scripts/office/validate.py out.pptx
python <pptx-skill>/scripts/office/soffice.py --headless --convert-to pdf out.pptx
python -c "
import pymupdf
d=pymupdf.open('out.pdf')
for i,p in enumerate(d,1): p.get_pixmap(dpi=105).save(f'slide-{i:02d}.jpg')"
```

**生成した画像を必ず目で見る。** コードを書いた直後は「そう書いたはず」の像が
頭にあるため、実際のレンダリングとの差に気づけない。特に確認するのは、
表の最終行がカードに隠れていないか、カード内の最終行が下端を割っていないか、
見出しが2行に折り返して本文とぶつかっていないか。

日本語フォントはLibreOffice側でIPAPGothicに置換される。Meiryoとは字幅が
違うので、プレビューでぎりぎり収まっている箇所は**本番では溢れる**と考えて、
1割の余裕を持たせる。

## 固有名詞

「アピシウス」「ティエリー・マルクス」は資料によって伏せる指示が出ることが
あるため、初出時に確認する。伏せる場合は「グランメゾン」「グループ直営店」
とする。社名・数値・法務の断定表現は、確認できていないものを断定しない。
