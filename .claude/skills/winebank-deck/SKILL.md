# WineBank 納品ドキュメント（PowerPoint）

## この会社の納品ルール

WineBankでは、**納品物は毎回PowerPoint（.pptx）で出す**と決まっている。

理由を理解しておくと判断がぶれない。納品先は経営会議・出店先の担当者・金融機関といった、
ファイルを開いてその場で議論し、そのまま抜粋して別の場に持ち回る相手である。
HTMLやMarkdownは編集して回覧できないので、途中で必ず誰かが手作業でPowerPointに詰め替えることになる。
最初からPPTXで出せばその手戻りがなくなる。

したがって：

- ユーザーが形式を指定しなくても、納品物であれば .pptx を作る
- 「HTMLで」「Markdownで」「Excelで」と**明示的に指定された場合はそれに従う**。ルールは既定値であって、ユーザーの指示を上書きするものではない
- .pptx に加えて、閲覧しやすいアーティファクトやサマリーを添えるのは構わない。ただし**納品物の本体は必ず .pptx** で、それを `SendUserFile` で渡す
- リポジトリで作業しているなら `docs/` にもコミットして、履歴を残す

## 進め方

### 1. 中身を固めてから作り始める

スライドを書く前に、伝えるべき結論・根拠・数字を確定させる。
元資料（契約書、見積、既存の分析）があるなら先に読み切って、
**出典のある事実と、こちらの推定・逆算値を必ず区別する。**
WineBankの資料は契約や投資の判断に使われるので、
推定値が確定事項の顔をして紛れ込むのがいちばん危ない。
スライド上でも「（予定）」「社内目標値」などで明示し、脚注に出典を書く。

### 2. `pptx` スキルと併用する

ファイルの作り方（pptxgenjsの書き方、既存デッキの編集、検証、画像化）は
`pptx` スキルに全部書いてある。**このスキルはその上に載るハウススタイルなので、
実際に作るときは `pptx` スキルも読むこと。** ここでは重複を書かない。

作成は原則 pptxgenjs のスクリプトを書く方式。生成スクリプトは捨てずに
`docs/` か作業ディレクトリに残す。次に数字が変わったとき作り直しが一瞬で済む。

### 3. ハウススタイルを適用する

配色・フォント・レイアウトの具体値は `references/house-style.md` に置いてある。
デッキを書き始める前に読むこと。要点だけ先に：

- 16:9（`pres.layout = "LAYOUT_WIDE"`、13.33" × 7.5"）
- ボルドー `8C2740` が主役の色。ワインの会社なので、この色は動かさない
- 日本語は Yu Gothic、数字と日付は Arial
- 表紙と締めは濃色地、中身は白地

### 4. 工程表・ガントチャートは同梱スクリプトを使う

WineBankは出店案件が続くので工程表の依頼が繰り返し来る。
毎回ゼロから描画コードを書くと時間もかかるしバーの位置がずれる。
`scripts/gantt.js` に日付から座標を計算するモジュールを置いてあるので、
`require` してデータを渡すだけにする。使い方はファイル先頭のコメントに書いてある。

### 5. QA してから渡す

`pptx` スキルのQA手順（`validate.py` → PDF化 → 画像で全スライド目視）を必ず通す。
そのうえで日本語資料では次を追加で見る：

- **数字の桁**。金額は3桁区切り、単位（円／千円／百万円）をスライド内で統一する。契約書から引いた金額は1円まで合っているか元資料と突き合わせる
- **年月日の表記ゆれ**。`2027年4月30日` と `2027/4/30` を混在させない。デッキ内でどちらかに寄せる
- **禁則と改行位置**。見出しが変なところで折り返していないか。折り返すなら意味の切れ目で改行を入れて制御する

### 6. 納品する

1. `SendUserFile` で .pptx を渡す（`status: "proactive"`, `display: "attach"`）
2. リポジトリ作業中なら `docs/` にコミットして push
3. チャットでは**中身の要点と、判断が必要な論点**を書く。ファイルの説明で終わらせない

## スライド構成の型

依頼の種類ごとに、だいたいこの並びになる。中身がないセクションは飛ばしてよい。

**工程表・スケジュール系**
表紙 → サマリー（結論・現在地） → 全体ガント → フェーズ別ガント（2〜3枚） →
マイルストーン一覧 → 資金・支払スケジュール → リスクと留意点 → 次のアクション

**提案・企画系**
表紙 → サマリー → 背景と課題 → 提案内容 → 数値計画 → 実行スケジュール →
リスクと対策 → 依頼事項

**分析・報告系**
表紙 → サマリー（結論を先に） → 分析結果（1論点1枚） → 示唆 → next step

どの型でも、**2枚目のサマリーで結論が言い切れているか**を最後に確認する。
決裁者はそこしか読まないことがある。

## 日本語スライドで気をつけること

- **1行の文字数は40字前後まで。** 超えると読まれない。文を切るか、体言止めにする
- **箇条書きは3〜5項目。** それ以上はスライドを割る
- **見出しは名詞句か言い切り。** 「〜について」で終わる見出しは中身が伝わらない。
  「工期は実質2ヶ月」のように、見出し自体が主張になっているほうが速く読める
- **このコンテナのQA描画は日本語フォントをIPAゴシックに代替する。**
  漢字・かな は全角固定なので折り返し位置はほぼ実機どおりに出るが、
  英数字混じりの行は幅がずれる。英数字の多いテキストボックスは1割ほど余裕を持たせる
