# 納品ファイルの命名規則

ユーザーに渡すファイル（納品物）は、**ファイル名だけで「いつの・何の書類か」「どの版か」が分かる**ようにする。
英語のスラッグや `draft.pdf` `output.pptx` のような名前で納品しない。

## 命名フォーマット

```
YYYYMMDD_宛先または案件_内容がわかる日本語タイトル.拡張子
```

- **YYYYMMDD** … 区切り記号なしの8桁。原則として**書面に記載した日付（発信日）**を使う。書面日付を持たない資料（スライド、集計表など）は作成・納品日。
- **宛先または案件** … 社外文書は「◯◯様」（法人宛は法人名＋様）、社内資料は案件名や物件名。不要なら省略可。
- **日本語タイトル** … 「地位承継依頼書」「事業計画書」「月次報告」など、書類の性格が分かる語を必ず入れる。
- 区切りは半角アンダースコア `_`。スペース、`/`、`:` は使わない。

### 例

```
20260825_三井不動産商業マネジメント様_赤れんがテラス_地位承継依頼書.pdf
20260825_北海道エアポート様_新千歳空港_店舗運営承継依頼書.pdf
20260901_社内_2026年10月期_事業計画.pptx
20260901_新千歳空港_ABC分析.xlsx
```

## 版（バージョン）の扱い

- **日付が版を表す。** 内容を改訂したら、新しい日付のファイル名で書き出す。古いファイルは残す（上書きしない）。
- **同じ日に作り直した場合**のみ、末尾に `_r2`, `_r3` を付ける。
  例：`20260825_北海道エアポート様_新千歳空港_店舗運営承継依頼書_r2.pdf`
- 相手先の指摘を反映した改訂版は、日付を発信日に更新し、書面本文の日付も必ず合わせる。
  **ファイル名の日付と書面内の日付は常に一致させること。**

## 原稿（ソース）ファイルの扱い

- HTML や Markdown などの**編集用ソースは、日付を入れない安定した名前のまま**にする
  （例：`succession-letter-akarenga-ptitsale.html`）。git の履歴で版を追えるため。
- **日付を付けるのは書き出した納品物**（PDF・PPTX など）だけ。
- ソースと納品物の対応は、格納フォルダの `README.md` に一覧で書き残す。

## 納品時の手順

1. 書面内の日付・文書番号を発信日に合わせる。
2. 上記フォーマットでファイル名を付けて書き出す。
3. ユーザーに渡す（SendUserFile など）ときも、この名前のまま渡す。
4. リポジトリに残す場合は納品物とソースの両方をコミットし、README の一覧を更新する。
