# 大量保有報告書の買付明細タブ作成

## 1. 何を作るか

既存の買付明細ブック（.xlsx）に、指定期間の新しいタブを 1 枚追加する。タブは 4 ブロック構成：

1. **日別買付集計** — `買付日 / 数量合計 / 買付額合計 / 取引数 / SBI東(無) / SBI PTS(無) / 楽天(東証) / 楽天(JAX)`
2. **作成方針** — 採用した集計ルールと、除外・未反映の明示
3. **買付明細一覧** — `No. / 買付日 / 数量 / 建単価 / 買付金額 / 証券会社・市場`
4. **保有株券等の数・保有割合の推移** — 報告義務発生日の自動判定つき

タブ名は既存の慣例に合わせる（例：`アディッシュ明細(825-911)`）。

## 2. 集計ルール（ここを外すと数字が合わない）

- **約定日ベース。** 受渡日ではない。SBI ポートフォリオの「買付日」＝約定日。
- **買い越し（取得）のみ計上。** 売却は別集計。
- **証券会社間の建玉移管は両建てとも除外。** 楽天の信用返済売埋と SBI の信用買建が
  **同日・同数量・同単価**で対応する場合、市場での売買ではないので売り・買いとも落とす。
  単価が 1 円でも違う行は別建ての実取引なので**必ず計上する**（同日でも除外しない）。
- **取引数**＝（約定日 × 市場 × 単価）の組合せ数。同一日・同一単価・同一市場の複数約定は 1 件に束ねる。
- 前タブ末の累計取得株数・累計取得価格を引き継ぎ、期末の平均取得単価まで出す。

## 3. データ読み取りの鉄則

- **建代金 ＝ 数量 × 単価 を全行で検算する。** 一致しない行は読み違い。必ず潰してから先に進む。
- **SBI ポートフォリオの「市場／期限」列を行ごとに確認する。** 同じ画面に `東/無` と `PTS/無` が
  混在し、繰り返し値は空欄表示になることがある。全行を `東/無` と決めつけない。
  PTS は `554.9` `563.9` `577.9` のような小数単価が出るのが手がかり。
  → **過去に PTS を東証と誤読して 1,200 株ずれた実績あり。**
- ポートフォリオは**買付日の昇順**。「N件中 a〜b件目」の表示から、対象期間が
  取得済みページに収まっているかを必ず確認する（前ページは全て古い日付）。
- **ポートフォリオは残存建玉のみ。** 期間中に建てて返済済みの玉は出てこない。方針欄に明記する。
- 画像が回転・低解像度で数値を確定できないときは**推測で埋めない**。
  読めた分で組み立て、読めない分は「未反映」と明示してユーザーにテキストでの提供を依頼する。

## 4. 検証（必須）

- `前回報告の保有株数 ＋ 本集計の取得株数 ＝ 現在の保有株数` が**ピタリ一致**するまで完成としない。
  差異が出たら PTS の読み落とし・楽天分の欠落・現物取得・返済済み建玉を疑う。
- 既存タブと重複する日付があれば、その日の数量・金額・取引数が**既存タブと一致**するか突き合わせる。
- 新タブ追加後、**既存シートが全セル差分 0** であることを確認する（openpyxl で両ブックを総当り比較）。
- 数式は LibreOffice (`soffice --headless --convert-to xlsx`) で再計算し、値を目視確認する。

## 5. 保有割合と提出期限

- **分母（発行済株式等総数）**は半期報告書・有価証券報告書・決算短信の
  「**提出日現在発行数**」を使う。決算短信の「期末発行済株式数」は期末時点なので古いことがある。
  新株予約権の行使で静かに増えるため、**報告書記載の分母が最新とは限らない**。
- **閾値は「直前の報告書に*記載された*株券等保有割合 ＋ 1%」で固定。**
  分母が後から増えても、記載済みの割合は遡って動かない。分子だけ新しい分母で割って比較する。
  直前報告の分母自体が誤っていた疑いがあるときは、記載値基準と訂正基準の**両方**を出し、
  早い方の期限を採るよう勧める。
- **報告義務発生日**＝初めて 1% 以上増加（減少）した約定日。その後さらに買い増しても発生日は動かない。
- **提出期限＝発生日から 5 営業日以内**（法27条の25第1項）。発生日の翌営業日を 1 日目として数える。
  → 過去実績で検証可能：発生日 2026/07/21(火) → 提出日 2026/07/28(火)。
  **日本の祝日を必ず考慮する**（海の日・山の日・敬老の日・秋分の日など）。
- 「直前の報告書」がどれかは**ユーザーに確認する**。未提出か提出済かで発生日も期限も変わる。

## 6. 成果物の受け渡し

- Drive 上の `.xlsx` は、利用可能なツールでは**中身を直接上書きできない**（タイトル／フォルダ移動のみ）。
- 65KB 規模のバイナリを base64 で転記するのは破損リスクが高いので**やらない**。
- 代わりに：**更新した .xlsx をユーザーに直接送付**し、あわせて同じ内容を
  **CSV の `textContent` で Google スプレッドシートとして同フォルダにアップロード**する
  （タブを右クリック →「他のスプレッドシートにコピー」で元ブックへ取り込める）。
- 版を重ねるときは**古いアップロードをゴミ箱に移す**。誤った結論の版を残さない。

## 7. やらないこと

- 個人の保有証券データを git リポジトリにコミットしない。スキル（手順）だけを残す。
- 分母・PTS・直前報告など未確定の要素を、確定したかのように書かない。条件付きで示す。
