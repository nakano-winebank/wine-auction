# 会員管理（ワイン購入後）

WineBank でワインを購入した会員の、購入後の資産・ランク・手数料・ワインマイルを扱うモジュール。
2026/8/31 中谷氏MTGの決定事項を実装の起点にしている。

| MTGでの決定 | 実装 |
|---|---|
| マイルをコミュニティ通貨として使う | `mile_transactions.channel` にレストラン・スクール・イベント・オークション等を記録 |
| 期間限定ポイントに 3〜6ヶ月の有効期限 | `mile_lots.expires_at`。種別ごとの既定は `MILE_VALIDITY_DAYS` |
| ランク別の還元率 | `member_ranks` テーブル（100万 3.5% / 400万 4.5% / 1000万 5.5%） |
| 回遊するほどマイルが貯まる | `kind='bonus'` の付与 API。行動連動マイルは 180 日で失効 |
| 上位ランクを目指したくなる見せ方 | マイ・セラーに次ランクまでの進捗バーと還元率の差分を表示 |

## ブラウザで通せる一連の流れ

CEO が画面だけで確認できるように、購入から失効までを会員自身が操作できる導線にしてある。

```
/member          口座がなければ「ワインを購入する」へ誘導
  ↓
/member/join     3プランを選んで購入 → 口座開設・保有登録・ランク付与・マイル付与が一度に走る
  ↓
/member          ランク／評価額／マイル残高／失効予定を確認
                 「マイルをつかう」チャネルを選んで交換（残高不足はエラー）
                 「マイルを購入する」有償パック（要フラグ・下記の法務注記を参照）
                 「1年進める」年次還元と失効を実時間を待たずに再現（要 DEMO_MODE）
```

### 購入プランはランク master から生成する

プランの金額は各ランクの `min_book_value` そのもので、本数は代表銘柄の単価から切り上げで逆算する
（`services/purchase.js`）。管理画面でランクの閾値や料率を変えるとプランが自動で追従するので、
金額・料率をコードに書き写す必要がない。代表銘柄を入れ替えたいときは `REPRESENTATIVE_WINES` を直す。

### デモ用の時間送り

`DEMO_MODE=1` のときだけ `/api/demo` が登録される。本番では環境変数を設定しないこと。

アプリ全体の現在時刻を仮想化すると会員管理以外にも影響が及ぶため、**逆に対象会員の台帳の日時を
N日ぶん過去へずらす**ことで時間の経過を作っている。本番コードが通る経路は一切変わらず、
影響範囲も指定した1会員の行に閉じる。日時をずらしたあとは、本番のバッチと同じ関数
（`expireLots` / `grantAnnualReward` / `accrueManagementFee`）をそのまま呼ぶ。

| 環境変数 | 既定 | 内容 |
|---|---|---|
| `DEMO_MODE` | 未設定 | `1` で時間送り API と画面のデモバーが有効になる。**プラン購入もこれで開く**（下記） |
| `MEMBER_MAIL_BATCH` | 未設定 | `1` で会員向け通知メールの日次バッチが動く。**本番では必須**（下記） |
| `MEMBER_EMAIL_FROM` | `EMAIL_FROM` に同じ | 会員向けメールの送信元。オークション通知と分けたいとき設定する |
| `MEMBER_EMAIL_REPLY_TO` | 未設定 | 会員向けメールの返信先。問い合わせ窓口を入れる |

## 法務対応（岩田合同法律事務所 意見書 2026年9月）

意見書の結論は「本マイルを発行することは法律上の問題なく実施できる」。
実装に効く指摘と、その対応箇所は次のとおり。

| 指摘 | 対応 |
|---|---|
| 年次マイルを「賃料」「リースの対価」と表現すると対価性が生じ、前払式支払手段に該当し得る | コード・UI・メール文面のいずれにも賃料／リースの語を使っていない。`sourceType='annual_reward'`、memo は「年次還元」。規約第2条3項でも「管理手数料に対する謝礼として無償で付与」と明記 |
| **有償でのマイル販売は意見書の対象外**（照会されていない）。意見書の論理からは前払式支払手段に該当する | `MILE_PURCHASE_ENABLED` で既定無効。台帳分離（`kind='purchased'` + `paid_amount`）と有償分だけの残高集計、供託モニタを実装済み |
| 消費者契約法10条。事前告知なく失効させる条項は無効となり得る | 失効30日前の予告メールは**法的要件**。送信ログを `member_notifications` に残し、宛先・日時・対象マイル数・失効日を後から証明できる |
| 経産省ガイドラインの6項目を明記し、容易に確認できる方法で公表 | `/terms/miles` に規約ページを用意し、会員画面のフッターと交換パネルからリンク |
| 景品表示法5条2号（有利誤認表示）。利用先ごとに充当レートが異なる場合は明示 | `mile_channels` にレートを持ち、**交換先を選ぶ前に**全チャネルのレートを画面表示。規約ページにも掲載 |

### 充当レート

レートは `mile_channels.yen_per_mile`。コードには持たない（`PATCH /api/admin/members/channels/:code` で変更できる）。
初期値は利用規約ドラフトの記載に合わせ、**提携グランメゾンのみ 0.5 円、その他は 1.0 円**。

なお master への初期投入は既存行を上書きしないので、この変更より前に作られた環境では
レートが 1.0 円のままになる。その場合は管理APIで設定し直すこと。

会員画面は交換先カードに「1マイル ＝ ¥○」を**常に**併記する。一律 1.0 円のときも省略しないのは、
レートを変えた瞬間に表示の有無が変わると、かえって気づかれにくくなるため。
利用時に適用したレートと充当額は `mile_transactions.yen_per_mile` / `yen_value` に残るので、
あとから master を変えても過去の取引の充当額は変わらない。

### 利用規約ページ

`/terms/miles`（`public/terms-miles.html`）。ログイン不要で読める。

**条文の正本は提案資料ブランチの `提案資料/ワインマイル利用規約_ドラフト.md`。**
条文を直したときは両方をそろえること。意見書の内部メモ（⚠️ 付きの検討事項）は会員に出すものではないので、
このページには載せていない。

付与率・充当レート・有効期間は条文に書き写さず、`GET /api/member/shop/program`（認証不要・公開情報）
から描画している。規約が「当社ウェブサイトに掲載する」と約束している数値そのものなので、
master を変えたときに規約の記載とずれないようにするため。

制定日はページ上部に表示している。条文を改定したら、正本と制定日の表記を両方そろえること。

なお元のドラフトには法務の検討事項（⚠️ 付き）が残っている。相続・会員資格の承継の扱い、
規約変更の予告期間、サービス終了の予告期間、マスターリース契約側の賃料の建て付けは、
確定版の条文には反映済みだが、法務での最終確認は別途必要。

## ⚠️ プラン購入は決済が未接続

`POST /api/member/shop/purchase` は、呼ばれた時点で保有ワイン（＝簿価）とマイルを発生させる。
決済を挟まないまま公開すると、**ログインできる利用者が任意回数呼んで資産とマイルを無制限に作れて
しまう**（作られたマイルはそのまま各チャネルで充当できる）。そのため `DEMO_MODE=1` のときだけ
実行でき、未設定なら 403 を返す。プラン一覧の取得は情報を返すだけなので閉じていない。

画面側も `planPurchaseEnabled` を見て、購入不可のときはプランを見せたうえで
「オンラインでのご購入を承っておりません」と案内し、確認パネルを開かない。

Pay.jp を接続する際は、このフラグ判定を**決済成立の確認に置き換え、決済IDで冪等にする**こと。
`purchasePlan()` 自体は決済成立後に呼ぶ想定のままなので、サービス層は変更しなくてよい。

## マイルは販売しない（2026年9月・経営判断）

**有償でのマイル販売は行わない**と決定した。無償で付与するマイルは資金決済法3条1項の
「対価を得て発行される」を満たさないため前払式支払手段に**該当せず**、財務局への届出も
発行保証金の供託も不要になる。

販売の導線（エンドポイント・サービス関数・パック定義・会員画面のパネル）は削除済み。
環境変数で再び開くこともできない。

**無償発行のみという前提は、コードで保証している。**

| 仕組み | 内容 |
|---|---|
| `miles.grant()` | `kind='purchased'` を明示的に拒否する。コードから有償ロットは作れない |
| `GRANT_KINDS` | `purchased` を含まない（reward / bonus / campaign / adjust のみ） |
| `getPurchasedOutstanding()` | 常に 0 を返すはず。0 以外は前提が崩れた合図 |
| 管理画面「有償発行の監視」 | 上記を常時表示。検出したら警告を出す |

`mile_lots.paid_amount` 列と `PURCHASED_KIND` 定数を残しているのは、**有償発行が存在しない
ことを機械的に確認し続けるため**。将来方針を変えて有償販売を行う場合は、財務局・顧問弁護士への
照会が先に必要になる（2026年9月の意見書は無償付与の3類型のみが対象で、有償販売は照会されていない）。

スキーマはサーバ起動時に `migrate()` が冪等に適用する。既存の `database.js` には手を入れていない
（SQLite のファイルパスを `SQLITE_PATH` で差し替えられるようにした一行を除く）。

## データモデル

- **member_accounts** — ユーザー1人につき1つの会員口座。`rank_code` は簿価から自動算定される。
  `locked_rank_code` を入れると簿価に関わらずそのランクで固定できる（特例対応用）。
- **holdings** — 購入した1明細＝1行。`acquired_unit_price` が簿価。`status` が `stored` / `shipped`
  の間だけ資産合計に入り、`sold` / `withdrawn` になると外れる。
- **holding_valuations** — 時価の履歴。最新の `as_of` の行が評価に使われる。
- **management_fees** — 期間ごとの手数料計上。同一期間の二重計上は弾く。
- **mile_lots** — 付与のロット。有効期限と残量を持つ。
- **mile_transactions** — 監査証跡。残高の正は `mile_lots.remaining_amount` の合計。
  利用時は適用した充当レート（`yen_per_mile`）と充当額（`yen_value`）も残す。
- **mile_channels** — 利用先と充当レートの master。レートはコードに持たない。
- **member_notifications** — 送信済み通知の記録。バッチの二重送信を防ぐためだけに使う。
- **club_memberships** — WineBank CLUB の会員資格。投資ランクとは別軸。ワイン未購入なら
  `member_id` は NULL のまま。
- **member_import_batches** — 一括インポートの実行記録（監査用。個人情報は持たない）。

## マイルの消込順序

有効期限が近いロットから引き当てる（FIFO by expiry）。期限なしのロットは最後に回る。
これにより、期限の近い期間限定マイルが先に消化され、失効を最小化できる。

```
付与: 還元35,000（期限365日）→ ボーナス3,000（期限180日）
利用: 5,000 → ボーナス3,000を使い切り、残り2,000を還元から
```

失効は `expireLots()` が担当し、`server.js` から1時間ごとに走る。
残高計算は期限切れロットを最初から除外するので、バッチの実行が遅れても残高が過大に出ることはない。

## 料率の変更

コード変更は不要。管理画面「会員管理 → ランク設定」で簿価下限・管理手数料率・マイル還元率を編集できる。
`PATCH /api/admin/members/ranks/:code` を叩いても同じ。

## 未着手（次の判断が要るもの）

- **オークション落札との自動連携** — 現状、保有ワインの登録は管理画面からの手動。
  `orders` が `paid` になったら `holdings` を自動生成する導線は、決済フローの確定後に入れるのが安全。
- **手数料のマイル充当** — 「管理費の一部をマイルで払える」設計は PL 側の議論が固まってから。
- **請求・決済連携** — `management_fees.status` は持っているが、Pay.jp への連携は未実装。
- **マイル有償購入の法務確認** — 上記のとおり実装は入れたが、財務局・顧問弁護士の確認が済むまで
  `MILE_PURCHASE_ENABLED` を立てない。あわせて、有償で購入したマイルが失効したときの
  返金・消費者対応の方針も決める必要がある。
- **決済連携** — 購入導線もマイル購入も決済は未接続で、台帳への記録だけを行っている。
  Pay.jp の決済成立を待ってから登録する導線に差し替えること。
- **インポートの実データ検証** — インポーターは実装済みだが、CLUB会員リスト・投資会員リストの
  現物でまだ検証していない。実ファイルを受け取ったら、まずドライランで対応付けと件数を確認する。
