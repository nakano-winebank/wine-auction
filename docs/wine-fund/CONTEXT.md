# 引き継ぎメモ（セッション分岐時点）

このファイルは、山本案スレッドと倉持案スレッドに分岐した時点での前提・経緯をまとめたもの。
数値の定義は `README.md`、モデル本体は `model.py` を参照。

## 案件の概要

株式会社WineBank（中野邦人 CEO）が、資産管理会社に対して総額5億円のワインファンドSPC
（GK-TK／適格機関投資家等特例業務による私募）の組成を提案している。

先方の登場人物：

| | 役割 |
| --- | --- |
| 山本様 | 窓口 |
| 高山社長 | 資産管理会社 代表 |
| 高岡先生 | 公認会計士 |

先方の投資基準は「**想定利回り20%（実績ベース）**」。**IRRは使わない** — 先方が用いる尺度が
「想定利回り」であるため、資料では「定常年間利回り」と「年平均利回り（5年通算）」の2つに
統一している。IRRという語を資料に登場させないこと。

## 2つの案

「出口の折半」から「SPCへ卸す時点の値入れ（時価−α）」へ移した。変更内容は `changes.js`
が生成する変更点資料に整理してある。

## 絶対に間違えてはいけない前提

### 「折半」は廃止した（2026年9月）

**現行の山本案に成功報酬（折半）は存在しない。** 過去の資料・メモには「折半＝投資家が
得た利益をWineBankと折半する成功報酬」という定義が繰り返し出てくるが、これは旧版の話。
現行は次のとおり。

```
投資家の取分 ＝ SPC税前利益 × 出資比率40%
投資家利回り ＝ SPC税前利益 × 40% ÷（総額 × 40%）＝ SPC税前利益 ÷ 総額
```

配分がプロラタであるため、**投資家利回りは出資比率そのものには依存しない**（WineBankの
持分が60%でも0%でも同じ）。倉持案は従来どおり折半のままなので、両案を同じ言葉で説明
しないこと。

### WineBankの取り分は「卸した時点」で確定する

```
時価（取得時点の加重平均売値）  定価比 75.00
α（時価からの控除率）          20.8%
SPC簿価 ＝ 時価 ×（1−α）       定価比 59.38（市中原価50.00に対し ＋18.8%）
```

出口で取るのは管理報酬（総額の年2%）のみ。回転12ヶ月・総額5億では、WineBank受取
145百万円のうち **85百万円（約6割）が運用成果によらず確定する**（値入れ75＋管理報酬10）。
成果連動は持分60百万円だけ。前回は178百万円のうち163百万円が成果連動だった。

**「投資家が儲からなければWineBankも儲からない」はそのままでは使えない。** 資料では
受取の内訳を明示してある。ここを曖昧にすると高岡先生に突かれる。

### 仕入価格と売値は投資家利回りから遮断される

卸値が時価に連動して決まるため、市中仕入が50→45に下がっても（±0.0pt）、売値が5%
下がっても（▲0.1pt）、投資家利回りはほとんど動かない。**効く変数は「在庫回転期間」と
「ワイン価格の上昇率」の2つだけ。**

この結果、**3シナリオを調達価格・売却価格で定義すると破綻する**（ポジティブがニュートラル
を下回る逆転が起きる）。現行はワイン価格の上昇率（年10%／6%／0%）で定義し直してある。
同じ理由で「値引き販売の禁止が最優先の防衛線」という旧資料の主張も成り立たない。

### 20%の分岐点に余裕がない

主線（回転12ヶ月・1stクローズ）で20.0%。**20%を割るのは回転12.0ヶ月**であり、
**主線がそのまま分岐点で余裕はない**。回転12ヶ月の達成は「上振れ条件」ではなく
**必要条件**。15ヶ月なら16.6%、18ヶ月なら14.4%で先方基準を下回る。この点は感応度・比較・
まとめの各ページに明記済みで、後退させないこと。

ワイン価格の年6%上昇も同様に前提条件（外すと13.3%）であり、「上乗せ」ではない。
**旧スキームより値上がり依存が強い**（▲4.0pt → ▲6.7pt）。

ただし**回転12ヶ月に必要な年間販売額は7.48億円→6.36億円に下がった**。卸値が上がったぶん
同じ5億円で持てるワインが減るためで、現状の販売実力（年5〜7億円）の範囲内に収まる。
ここは旧スキームより条件が良い。

### 卸値（時価−α）が最大の利益相反論点

旧スキームでは「現物出資の評価方法」が論点だったが、現行では**全量が時価−αで入る**ため、
論点は卸値そのものに移った。αを契約上20.8%に固定し、時価の算定方法（B2B卸値とB2C売値の
加重平均）も契約に明記する設計にしてある。

**WineBank出資分に対応する値入れは自己取引になる**（自社の現物出資に自ら値入れする形）。
内部利益の消去要否を会計・税務の両面で組成前に確定させる必要がある。資料の利益相反ページと
リスクページに明記済み。

### ファンドの実質規模が縮む点

SPC簿価が50.50→59.38に上がるため、同じ5億円で持てるワインは定価換算で約15%少なくなる。
利益は1本あたりで発生するので、**ファンドが生む付加価値そのものが年218百万円→185百万円と
約33百万円縮む**。WineBankはその分を卸値で前取りしているので自社の損得はほぼ中立だが、
投資家から見ると「同じ2億円でより少ないワインを持つ」構造になる。変更点資料に記載済み。

### セカンドクローズは販売実力とセット

総額を5億→10億にすると、回転12ヶ月に必要な年間販売額も7.48億→14.96億へ倍増する。
現状の販売実力（年5〜7億円）の2倍を超えるため、規模拡大は販売チャネルの拡大とセットで
判断する設計にしてある。ここを緩めないこと。

### 販売実力とのギャップ

回転12ヶ月には年間7.48億円の販売が必要。WineBankの現状の販売実力は年5〜7億円で、
10億円は困難。この差を埋める主たる手段は**組入銘柄の選定**（流動性の高い銘柄をSPCに入れる）。

### 在庫配分の公平性

WineBank自己勘定在庫との配分は**在庫比率によるプロラタが原則**。プロラタで決し得ない部分に
ついてのみSPC優先。「SPC在庫を完売するまで自己勘定を売らない」という運用は、銘柄ごとに
商品構成が異なるため実務上成立しない。契約別紙1に明文化済み。

## 2026年9月に受け取った修正版について（記録）

`build.js` が生成した現物出資型の資料に中野が直接加えた修正版を受領した（ファイル自体は
手元に残っていない）。**数値の変更はなく**（20.4%・50.50・12.2ヶ月などすべて一致）、
変更は文言のみだったが、次の問題があった。同じ修正を再度入れる場合は注意する。

- **「原価」→「原価（熟成考慮）」の一括置換が崩れていた。** 二重括弧6箇所、余分な閉じ
  括弧1箇所、そして「投下原価利益率」の語中への挿入7箇所（「投下原価（熟成考慮）利益率」）。
  最後のものは専門用語が壊れるため特に不可
- **ラベルと数字が矛盾する。** SPC取得原価50.50は熟成を織り込んでいない（市中原価50.00＋
  現物譲渡1%）。熟成1年・年10%を実際に入れると投資家利回りは20.4%→16.8%で20%を割る
- **p04「販売計画」の脚注が削除された。** ファーストクローズの販売実力ギャップ（年5〜7億円）
  に触れた記載はこの脚注が唯一で、資料から消えた（20%の分岐点0.2ヶ月は他4ページに残存）
- 表紙のバッジから「山本案｜」が削除され、倉持案との区別が表紙でつかなくなった

変更点資料（DOCX）には次の追記があった。

> 原価は毎年熟成させる毎に10％ずつ上昇（もしくは時価算定×70〜75％）を想定（確定ではない）

なお「時価算定×70〜75%」は時価の定義（定価100か、ネット最安80か）で取得原価が56〜65に
振れ、投資家利回りは7.3%〜16.1%まで動く。定義を先に決めないと試算できない。

## 品質確認の手順

PPTX/DOCX を書き出したら必ずレンダリングして目視確認する。LibreOffice の行高は指定値より
広がることがあり、表がカードや脚注を突き抜ける事故が繰り返し起きている。

```bash
soffice --headless --convert-to pdf --outdir qa foo.pptx
pdftoppm -png -r 96 qa/foo.pdf qa/s      # 各ページを画像化して確認
```

**環境構築（コンテナが素の状態の場合）。** LibreOffice は core/common だけしか入っておらず、
そのままでは PPTX も DOCX も読めない（`Error: source file could not be loaded`）。また
游明朝・游ゴシックが無いため、代替フォントを当てないと行高の判定が実機とずれる。

```bash
apt-get update && apt-get install -y libreoffice-impress libreoffice-writer poppler-utils
apt-get install -y fonts-ipafont fonts-noto-cjk
# /etc/fonts/local.conf で 游明朝→Noto Serif CJK JP、游ゴシック→Noto Sans CJK JP を alias
```

日本語ファイル名のまま `soffice` に渡すと読み込みに失敗することがあるため、作業用ディレクトリへ
ASCII名でコピーしてから変換すると安定する。

## これまでの主な指摘（再発させないこと）

1. 粗利の定義を変動販売費の前後で取り違え、ページ間で不整合を起こした → 粗利は**変動販売費控除後**
2. 「エクイティ利回り」という表記はデット／レバレッジと混同されるため使わない →
   「投資家利回り」「WineBank側」と分けて表記する
3. 月次の整数グリッドで丸め誤差が出たため、キャッシュフローは日次グリッドで計算している
4. 計算していない数値を表に書いた事故がある → 数字は必ず `model.py` 経由で算出する
5. 山本案の資料は数値を手打ちしない構成にしてある。`structure.py` が `figures.json` を
   書き出し、`build.js` と `changes.js` がそれを読む。**前提を変えたら必ず
   `python3 structure.py` を実行してから資料を生成すること**
6. `model.py` は両案共通。倉持案に影響させないため、変更は既定値を変えない形（例：
   `monthly()` の `period_days=180`）に留め、変更後は `python3 kuramochi.py` で
   倉持案の数値（21.0%／16.7%／105百万）が動いていないことを必ず確認する
